the first slice of the provider wave

Ported behind one plain header, classic side, folder picked up by `cmake/providers.cmake` on its own:

- `client_policy()` -- 30s connect / 5min read / 30s write, `retry_on_connection_failure`, redirects, said by the port's `http_policy`;
- `cleartext_is_safe(url, headers)` -- the port's fail-closed guard asked without a throw: no credential under plain `http://` to a host that is not this machine's (the four header names the Kotlin side counts, LAN/Tailscale/loopback allowed);
- `local_host(host)` -- the port's home range: loopback, RFC-1918, link-local, Tailscale, bare names and `.local`/`.lan`/`.home`/`.internal`.

`test/provider_http_test.cc` says all three whole (34 expectations' worth of ceilings, refusals and homes).

what is deliberately not here

The asking that uses it: wiring retries into `run`/`loop` and the cleartext guard into the asking would stand exactly on `run.cc`/`loop.cc`/`provider.cc` -- the files the open #13/#8/#9 are already on -- so the policy waits on the shelf until those land, the same way the core reshape waits on #13.
